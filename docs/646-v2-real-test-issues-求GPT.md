# #646-v2 实测暴露的新问题（2026-08-17 第二轮实机测试后）

> 本文只写**实测中新出现、之前评审未覆盖**的问题——设计层面的老问题不重复。
> 每项：现象 → 根因 → 待拍板。

---

## 新问题 1：分轮执行导致"计划卡弹得太晚"

**现象**：模型**分批调工具**（每轮 1-2 个：先 web_search×2 → 再 paper_get×2 → 再 write_file）。harness 按 turn 累计工具名判定——**第一批工具已经执行完**，到第 2-3 批才累计到阈值弹卡。用户看到：**AI 已经搜了几个东西，突然弹计划卡**——像"先斩后奏"。

**根因**：LLM 不一次性给出完整工具序列（受 max_tokens/上下文限制，实际分 3-6 轮）。harness 只能在"看到足够多工具名"时才敢判定。

**待拍板**：
1. 接受现状（弹卡时机 = 累计达阈值的那批工具执行前）？
2. 还是**两阶段**：turn 一开始就弹"意图确认"（标题=用户请求摘要，无步骤明细）→ 用户确认 → 模型放开跑 → 模型自己给详细计划？——这其实回到 GPT 提过的 Intent Plan，但当时说演示不需要——现在实测证明**需要**（否则弹卡时机尴尬）

## 新问题 2：计划卡步骤只有工具序列，质量不够

**现象**：实测计划卡步骤显示「搜集资料/阅读论文/创建文档」——是 harness 按工具名映射的**泛化短语**——用户看不到**具体计划**（搜哪些库？读哪几篇？报告什么格式？）。

**根因**：harness 弹卡不依赖模型计划文本（GPT：不让模型写计划防说谎）——但**只给工具序列**导致计划卡信息量低。

**待拍板**：信息平衡——harness 生成步骤时能否注入**工具参数摘要**（如 web_search 的 query / write_file 的 path）？「搜集资料（MOF-5 合成）」比「搜集资料」有用得多——参数来自 tool_calls 的 arguments（harness 有），不依赖模型写计划。**做不做？**

## 新问题 3：modify 循环依赖模型自觉，无 harness 校验

**现象**：用户点[修改计划] → 工具返回 modify_requested → **模型自己决定**重新规划并再次调用——如果模型**不重调**（继续执行/放弃），用户白点了。

**根因**：modify 是"模型主动腿"的循环——harness 不知道 modify 后模型有没有照做。

**待拍板**：harness 要不要接管 modify 循环？（收到 modify_requested → harness 记录"本 turn 进入 modify 态" → 模型下一轮若**不是** ask_user_plan_confirm 而是执行工具 → harness 强制拦截/再次弹卡？）——工作量 vs 可靠性。

## 新问题 4：ActionCard 的 sha256 从哪来

**现象**：ActionCard 设计显示文件 sha256（防确认 A 上传 B）——但**上传工具执行前**，harness/模型**还没有文件指纹**（文件内容未读）。

**根因**：sha256 需要预读目标文件——谁在什么时机算？上传工具自己算（执行内）→ 但那时已过确认点。

**待拍板**：
1. 上传工具执行时**先算 sha256 → 弹 ActionCard（带指纹）→ 确认后才真正上传**——工具内部两段式？
2. 还是 harness 在 ActionCard 弹卡前预读文件算 hash？（成本：每次上传多一次文件读）
3. 还是演示阶段 ActionCard 不显示 sha256（显示文件名/大小即可），指纹对接 #674 上传协议时再加？

## 新问题 5：同一 turn 内 PlanCard + ActionCard 的时间线

**现象**：多步骤任务含上传——PlanCard（任务启动）确认 → 执行 → 上传时 ActionCard——**两张卡同 turn**。用户感受如何？实测还没走到这步（上传链路未打通——qraft 上传工具在测试环境不可用）。

**待拍板**：
1. 演示时上传动作怎么触发？（本地 mock 上传 / 真实 qraft token？）
2. ActionCard 出现时 PlanCard 已折叠——时间线是否清晰？（计划卡收起 → 执行中 → 危险卡弹出——用户能不能理解"这是同任务的不同确认"）

## 新问题 6：#729 体验问题是否纳入 #646-v2

**现象**（另开 issue #729）：① 发送后首字延迟数秒（无"正在思考"反馈）② 切换 session 思考消失。

**待拍板**：
1. 两个问题修在 #646-v2 分支还是独立 PR？（#729 与卡片无直接关系，但"正在思考"占位和计划卡出现时机耦合——卡片弹卡前用户看到"思考中"还是"无响应"直接影响体验）
2. "正在思考"占位优先级——计划卡出现前用户需要看到 AI 在工作（否则以为卡死）

## 新问题 7：自动模式的非阻塞展示与"思考中"的关系

**现象**：Auto 模式设计为 TaskTimeline 展示（📋 AI 计划 ✓⟳）——但实测还没实现。用户在 Auto 模式发任务：计划卡不弹（非阻塞）→ 用户看到什么？——如果"思考中"占位 + 执行进度都没有 → Auto 模式看起来像"无反馈跑完"。

**待拍板**：Auto Timeline 是不是**必须**先于演示？（没有它，Auto 模式体验=黑箱）

## 新问题 8：计划卡确认后"已选择开始执行"的文案与折叠

**现象**：实测确认后卡片显示"已选择「开始执行」"——已改为折叠成一行（+ 展开详情）——但**折叠后用户还想看执行进度**（步骤 ✓⟳）——折叠与进度可见矛盾。

**待拍板**：确认后折叠一行 + 底部进度（如「3/5 步骤进行中 ⟳」）？还是 running 态保持展开、仅 completed/cancelled 折叠？（之前 Kimi 评审确认卡时"执行中保持展开"被认可——PlanCard 是否同样？）
