## 一、PR #684 —— 确认卡（collab gate + 契约扩展）

### 干什么
两条腿实现"执行前确认"：
1. **模型主动腿**：注入 `ASK_USER_CONFIRM_INSTRUCTION` 提示词——模型可在方案/多步操作前主动调 `ask_user_confirm_card` 工具弹卡
2. **harness 强制腿**：legacy orchestrator 插桩 **collab gate**——按「工具风险 × 用户模式」矩阵**规则自动弹卡**，不依赖模型自觉（issue #646 主路径）

### 解决什么 issue
- **#646**：关键步骤执行前卡片弹窗确认（P0 实验组+平台组）
- **#674 契约部分**：确认卡支持校验警告（warnings）+ 产物绑定（metadata: run_id/artifact_sha256）
- 顺带：修复桌面主路径（legacy）不弹卡的根因（提示词只注入 KUN + gate 没接）

### 实现方法（架构）
```
Tool Call
   │
   ▼
Permission Engine（Safety：能不能执行）
   │  审批弹窗（需要时）→ approval_resolved 标记
   ▼
Collab Gate（Collaboration：用户是否同意这个动作）
   │  collab_policy.evaluate(tool_name, autonomy_mode)
   │  ├─ DENY  → denied_by_policy（plan 模式拦截）
   │  ├─ CONFIRM → 弹确认卡（无通道降级放行）
   │  └─ ALLOW → 直接执行
   ▼
Sandbox → Execute
```

关键设计：
- **风险矩阵**（collab_policy.py）：READ_LOCAL/READ_EXTERNAL/WRITE/EXEC/EXTERNAL/PAYMENT/DESTRUCTIVE × 模式（plan/manual/supervised/autonomous）→ ALLOW/CONFIRM/DENY
- **autonomy_mode 真实路径**（P0-1 修复）：`autonomy_mode_from_policy()`——turn.execution_policy（桌面模式选择器）→ plan/ask/manual/edit/auto → AutonomyMode
- **双弹消除**：web_fetch 移出 EXTERNAL（前端操作审批已覆盖）；exec/上传类审批通过后 `approval_resolved` → gate 跳过
- **并发安全**（P1-4）：emitter 按 session_key 隔离
- **契约扩展**：ask_user_confirm.py 加 `warnings`（B 级校验警告必上卡）+ `metadata`（run_id/artifact_sha256 确认绑定防 TOCTOU）
- **卡片 UI**：中文标题（确认访问外部网页？）、URL 域名高亮、倒计时「⏱ 1:47 后自动取消」、完成式 resolved 态、执行中保持展开、居中 toast——经 Kimi k2.6 三轮视觉评审迭代

- pytest：kun_runtime gate 12 / execution 413 / ask_user_confirm 契约 25
- vitest 168（ConfirmCard 15 含警告区/元数据/折叠断言）/ tsc 0

### 干什么
1. 回答中的 ```` ```mermaid ```` 代码块 → **MermaidBlock 组件**渲染成 SVG 流程图
2. 正文 `【n】` 引用标 → **CitationAnchor**——点击打开来源（DOI/URL），文末参考文献解析成注册表

### 解决什么 issue
- **#671**：回答支持可视化流程图渲染与引用来源标注（对标 WorkBuddy——"冷冻造粒基本零 BET 损失"无出处问题）

### 实现方法
**Mermaid 渲染链**（ChatGPT 决策落地）：
```
chat:delta 流式 ──→ MermaidBlock streaming=true → 📊 占位符（绝不渲染残缺语法）
chat:final ──→ MermaidBlock streaming=false → mermaid.render() → SVG（sha256 缓存）
失败 → 降级代码块 + ⚠ 提示
```
- `securityLevel: 'strict'`（HTML 编码/禁 click）；`mermaid.render()` 非全局 `run()`；版本精确锁定 11.16.1
- streaming 只对最后一条 assistant 消息传 true（P1-1：历史图不消失）

**Citation 解析链**（ChatGPT 决策 6/7）：
```
模型输出【1】【2】→ remark 插件（text-node split → link#citation-N，跳过 code/inlineCode）
→ CitationAnchor（点击 → doi.org/URL）→ 文末「### 参考文献」段解析成 registry
```
- 过渡期：参考文献来自模型（model_declared）——UI 不声称已验证；对接 #547 SourceRecord 时做验证

## 三、PR #686 —— qraft 上传 Checkpoint 协议

### 干什么
为 qraft-workflowspec-export Skill 定稿**两阶段可恢复上传事务协议**——Skill 按此实现"校验 → 方案确认 → OAuth2 上传 → 重试"全流程。

### 解决什么 issue
- **#674**（P0 平台组）：Skill 上传全流程无规范——方案确认/产物校验/凭据管理/上传重试全无承载

### 实现方法（Checkpoint Protocol v1）
```
Phase 1: export + validate + 写 checkpoint（run_id + artifact sha256）→ 进程退出
Agent 读 checkpoint → 弹确认卡（warnings/metadata 契约来自 #684）
resume: 重新加载 checkpoint（不信模型传回的 hash）→ 重算 sha256 比对
  ├─ 一致 → OAuth2（lazy refresh + double-check lock）→ 上传
  ├─ 不一致 → ARTIFACT_CHANGED_AFTER_CONFIRMATION 拦截（防 TOCTOU）
  └─ MODIFY 3 次上界 → 强制上传/终止二选一
```
- 产物规范：只两份正式 JSON（definition + run，无 bundle——官方 schema 只认两种）
- 重试策略（ChatGPT 最终评审）：**无幂等不盲目自动重试**——definite-safe retry vs ambiguous → `UPLOAD_STATUS_UNKNOWN`
- 401 = refresh once + retry once；expires_at 缺失/refresh 失败 → `REAUTH_REQUIRED`
- 项目信息：UUIDv5（幂等）/标题/描述 → `run.extensions.x-project-*`；技术路线 → `definition.graph`
