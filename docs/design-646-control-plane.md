# MiQi Agent Control Plane——#646 重构架构（GPT 评审定稿）

> 状态：**架构重定义**（2026-08-15，GPT 评审）——取代原"逐工具弹卡"设计
> 核心转变：**#646 确认卡 = Agent 计划决策点，不是另一套审批**

---

## 1. 四个层次的定义（先固定关系）

```
                    User
                     │
                     ▼
         ① Execution Mode  （用户体验层：我希望 AI 怎么工作？）
                     │
                     ▼
         ② Agent Planning Layer（计划决策点 = #646 Plan Card）
                     │
                     ▼
         ③ Permission/Safety Engine（审批设置：允许哪些行为）
           ┌──────────┬──────────┬──────────┐
           │ command  │  file    │ network  │  （工具级审批）
           └──────────┴──────────┴──────────┘
                     │
                     ▼
              ④ Execute（执行 + 进度展示）
```

**顺序关键：计划确认在前，权限审批在后。**

---

## 2. 重新定义三个东西

### ① Mode（体验层）——现在/新

| Mode | 旧含义（含混） | 新含义 |
|---|---|---|
| Plan | 只规划 | 只规划（不动手） |
| 手动 | 每步确认 | **高级模式**（开发者调试）：逐步确认，含普通文件审批 |
| 允许编辑 | 写自动风险确认 | **默认推荐**：可改 workspace，无外部副作用自动；文件审批不弹 |
| 自动 | 完全自主 | **80% 自主**：workspace 全自动 + **外部副作用（上传/删除/支付）仍确认**——auto 不是无限权限 |

### ② 审批设置（Safety 层）——命名与粒度

- **「审批绕过模式」→ 改名「自主执行策略」**（"绕过"暗示安全关闭，误导）
- 白名单粒度：**工具 + 场景**（如「科研检索：web_search/web_fetch 允许，范围=论文网站」）
  而不是 url1/url2 逐条维护

### ③ #646 Confirm Card——从"审批"变"计划决策点"

| 场景 | 弹卡 |
|---|---|
| **多步骤任务 / Skill / 外部副作用组合 / 长任务** | ✅ **Plan Card**（计划 + 所需权限清单，确认一次） |
| 单个工具调用 | ❌ 不弹（自动执行） |
| 文件危险操作 / 命令 / 上传 / 删除 / 支付 | ✅ **危险动作卡**（单独，受 mode + 设置影响） |
| 普通文件审批（write_file 等） | ❌ 默认不弹（允许编辑/自动模式） |

## 3. 新模式矩阵（最终规则）

| 模式 | Plan Card | 普通文件审批 | 危险动作 |
|---|---|---|---|
| Plan | ✅ 有 | ❌ 无 | 🚫 禁止 |
| 手动（高级） | ✅ 有 | ✅ 有 | ✅ 有 |
| **允许编辑（默认推荐）** | ✅ 有 | ❌ 无 | ✅ 有 |
| 自动 | 少量 | ❌ 无 | ✅ 有 |

**关键原则**：
- 普通用户（允许编辑）→ 计划确认一次 + 危险动作确认一次——**不看每一个文件审批**
- auto 不是"无限权限"——删除整个项目/上传公司数据/付款仍停

## 4. UI 体验目标（参考 Claude Code / Cursor Agent）

```
✨ 生成实验报告                    ← Plan Card（一次）
   计划：
   ① 搜索相关论文
   ② 提取实验数据
   ③ 创建 workflow
   ④ 上传 Qraft
   需要权限：
   🌐 网络访问 · 📄 文件创建 · ☁ Qraft 上传
   [开始执行]

   执行中（进度展示，不弹卡）：
   ✓ 搜索论文
   ✓ 生成报告
   ○ 上传 Qraft

   ⚠ 即将上传 workflow.json     ← 危险动作单独卡
   [取消] [确认上传]
```

对比旧实现（被砍掉的 70%）：确认访问网络？确认创建文档？确认执行任务？——连续三卡。

## 5. 代码落点（从"逐工具 gate"改为"计划级确认"）

| 组件 | 现在（逐工具弹卡） | 重构后（计划级） |
|---|---|---|
| `collab_policy.py` | 风险矩阵（工具×模式 → 弹卡） | **触发条件重定义**：多步骤/Skill/副作用组合 → Plan Card；危险动作清单 → 危险卡；单工具不弹 |
| `orchestrator.py` gate | 每次工具调用前弹 | 仅**危险动作**弹（upload/delete/pay/destructive）；Plan Card 由 Agent 规划阶段触发（新） |
