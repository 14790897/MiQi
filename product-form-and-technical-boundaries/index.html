    MiqroForge Desktop V1 产品形态及技术边界说明¶

    版本：2.0 ｜ 适用版本：MiqroForge Desktop 0.20.0（Alpha）｜ 依据：代码仓库现状（apps/desktop/ 与 miqi/ 实际代码）

    0. 文档说明¶

    本文档定义 MiqroForge Desktop V1 的产品形态与技术边界。核心章节（第 2 章）逐页描述桌面应用当前实际实现的功能——全部从代码核实，不含规划中的能力；第 3 章说明支撑这些功能的技术约束与 V1 明确不做的范围。

    1. 产品定位¶

    MiqroForge Desktop 是一个本地优先的个人 AI 代理桌面工作台：Electron 桌面界面 + Python 运行时引擎，提供有记忆、有技能、能操作文件、能执行定时任务、可扩展工具生态的个人 AI 助手，而非单纯的聊天机器人。

    项 值
    产品名 MiqroForge Desktop（对外书面/界面/安装包名）
    内部标识 miqi-desktop / appId com.miqi.desktop（保留，不随更名修改）
    当前版本 0.20.0（Alpha），MIT 许可证
    形态总述 一个运行时、多种前端：桌面应用为主，CLI/TUI/消息渠道网关/Cron 共享同一运行时

    2. Desktop 当前功能全景¶

    2.1 应用框架与启动流程¶

    首次启动流程（App.tsx → features/setup/）：

    1. 隐私确认门（PrivacyConsentGate）：同意状态本地持久化，协议版本更新后老用户重新确认；E2E 环境自动跳过；
    2. 设置向导（SetupWizard）：环境检测（打包版自动识别内置 miqi-bridge.exe）→ WSL2 检测与配置（仅 Windows）→ Provider 配置（API Key / API Base URL / 默认模型）→ 工作目录；
    3. 进入主界面后可从设置页重新打开向导。

    主框架：

    组件 功能
    Sidebar 侧边栏 会话任务板（见 2.2）、导航入口、宽度可拖拽调整
    TopBar 顶栏 当前工作区显示、审批设置快捷入口
    StatusBar 底栏 运行时状态、模型已配置状态显示
    ApprovalBypassBanner 审批绕过模式开启时的常驻警示横幅，点击直达审批设置
    ConfigHotReloadListener 监听配置变更，修改后自动热生效，无需重启
    ApprovalModal / UserInputProvider 全局审批弹窗与用户输入确认通道

    2.2 聊天（ChatConsole）— 核心交互界面¶

    会话任务板（Sidebar）：

    • 会话列表按状态过滤：全部 / 进行中 / 待审阅 / 已完成，各状态带计数徽标；
    • 新建会话（+）：空会话自动复用、有内容才新建，带防重入锁与 1.5s 超时兜底；
    • 无限滚动（IntersectionObserver 分页加载）；
    • 右键菜单：标记为进行中/待处理/待审阅/已完成、在文件管理器中打开（定位工作区）、重命名、重置状态、归档、删除；
    • 批量操作：删除全部任务、归档全部任务；
    • 会话条目显示工作区路径与更新时间（相对时间，如「x 天前更新」）；
    • 启动时预热技能索引，避免首次打开技能面板卡顿。

    消息与对话能力：

    • 多轮对话、流式响应、打字机逐字动画（按会话独立推进，切会话后恢复补齐）；
    • 随时中止 Agent 执行（abort）；中断回合恢复卡（InterruptedTurnCard）：进程退出/中断后携带执行快照，可一键继续；多条历史线程可选择恢复（pickThreadToResume）；
    • 附件：图片（拖拽/粘贴，FileReader 转 dataUrl，历史图片按需懒加载避免内存峰值）、文档（docx/pptx/xlsx/pdf 等 23 种格式识别并分类型显示）、文本；
    • 工具调用可视化：工具名/参数摘要/图标，exec 命令内联输出，子代理（subagent）结果独立样式展示；
    • 文件变更展示：DiffView 统一 diff 对比，TrackedFileCard 跟踪文件卡支持 diff / revert / accept 操作；
    • 办公文档预览卡片：DocxPreview、SpreadsheetPreview、HtmlPreviewCard（SandboxHtmlFrame 沙箱 iframe 渲染，防脚本逃逸）；
    • 内容渲染：Markdown + GFM（表格/任务列表）、180+ 语言代码高亮、ThinkBlock 推理块折叠、ReasoningModeSwitch 推理模式开关；
    • 确认卡（ConfirmCard/ConfirmCardArea）：运行时反向向用户提问/请求确认（UserInput 通道），支持文本与选项；
    • 会话内操作：重命名（同步刷新侧栏）、工作区绑定与切换、消息时间分组。

    2.3 工作区（WorkspacePage）¶

    • 文件树浏览（树形结构 + 右键菜单）；
    • 文件操作：新建文件/文件夹、重命名、删除（删除有不可撤销确认框）；
    • 文本编辑器：未保存更改检测（「未保存」徽标）、Ctrl+S 保存、保存中状态、切换文件时未保存确认对话框；
    • 预览模式：Markdown 与 HTML 文件即时渲染预览（代码/预览切换）；
    • 文件版本操作（files API）：diff 对比、revert 回滚、accept 接受变更；
    • 打开方式：系统外部程序打开、在文件管理器中定位、HTML 用浏览器打开、另存为（saveAs，下载 base64 数据）。

    2.4 会话管理（SessionExplorer + ArchivedTab）¶

    • 双栏布局：会话列表（刷新、运行中智能体状态徽标——5 秒轮询、更新时间）+ 详情面板；
    • 详情面板：消息记录预览（用户/助手/tool 消息分样式，Markdown 渲染，超长截断）；
    • 会话操作：打开会话、复制 session key、删除；
    • 旧版会话认领：旧版 MiQi 会话可一键认领到当前桌面客户端（claimLegacy）；
    • 客户端隔离错误提示：无权访问其他客户端会话、加载失败分类提示；
    • 归档管理（设置 → 归档标签）：已归档会话列表，可恢复或永久删除。

    2.5 计划与任务追踪（PlanTracker）¶

    • Agent 复杂任务计划的实时步骤面板：pending（⬜）/ in_progress（🔄）/ completed（✅）/ skipped（⏭️）四态图标 + 颜色区分，随执行实时更新。

    2.6 审批与权限¶

    审批中心（ApprovalsPage + ApprovalModal）：

    • 审批队列：待审批命令列表（命令/决策/时间/会话），聊天内通过 ApprovalModal 弹窗即时处理；
    • 审批绕过模式五开关：全部绕过、命令审批、文件写入审批、工具确认、网络审批；
    • 白名单管理：新增白名单（永久放行）、清除永久规则；
    • 审批历史查询；
    • 运行时未启动时页面友好降级提示。

    权限策略（PermissionsPage）：

    • 文件系统规则：读取/写入各自独立策略——始终需要审批 / 无需审批 / 白名单模式 / 禁止；
    • Shell 命令审批：仅危险命令（默认）/ 允许所有 / 全部阻止；
    • 网络策略配置。

    2.7 智能体（AgentPanel）¶

    • 运行中智能体列表：类型、标签、ID 与状态（空闲/思考中/执行中/已完成/错误/已中止，彩色状态点 + 动效），新智能体 spawn 事件自动刷新。

    2.8 扩展能力管理¶

    MCP（MCPsPage）：

    • MCP 服务器列表与配置：名称、连接类型（Command 命令行 / URL 远程）、命令、工具超时（秒）、描述；
    • 网关模式：按需激活工具，避免全量加载。

    技能（SkillsPage）：

    • 技能列表与详情查看（左侧选择右侧详情）；
    • 新建技能（名称 + 描述）、删除技能。

    插件（PluginMarket）：

    • 已安装插件列表：名称、版本、描述、状态（已启用/已禁用/错误）；
    • 启用/禁用切换、卸载（确认框）；
    • 空态提示安装方式：放入 ~/.miqi/plugins/ 或 <workspace>/.miqi/plugins/。

    2.9 记忆与经验¶

    记忆（MemoryPage）：

    • 记忆文件管理（USER.md / MEMORY.md 等）：文件列表、选择查看与编辑、新建、未保存标记；
    • Lesson 经验教训记录（Bad/Better 对照）。

    经验（ExperiencePage）：

    • 经验记录列表：规则（正确行为 / 错误行为 / 参数）与历史记录浏览。

    2.10 定时任务（CronPage）¶

    • 定时任务列表：ID、调度表达式、下次运行时间、最近状态、创建时间、消息；
    • 创建与删除定时任务。

    2.11 设置中心（SettingsPage，22 个标签页）¶

    按功能域分组，每项均可独立配置并保存：

    标签 当前配置项
    通用 智能体名称、默认模型、Temperature、Max Tokens、工作目录；重新打开设置向导入口
    模型（Providers） 模型提供商管理：Provider 选择、API Key、API Base URL、默认模型
    渠道（Channels） 消息渠道接入配置（Feishu/Lark 等）、消息合并窗口时间（0=关闭）
    审批 同 2.6 审批中心
    工作区 同 2.3 工作区
    Web 工具 Web 搜索、Web Fetch、论文研究工具的提供商与参数配置
    外观 主题、UI 字号、代码字体大小、表情样式、对比度、减少动态效果（跟随系统）、侧边栏半透明毛玻璃、指针光标
    智能体 同 2.7 智能体
    技能 同 2.8 技能
    MCP 同 2.8 MCP
    记忆 同 2.9 记忆
    经验 同 2.9 经验
    权限 同 2.6 权限策略
    插件 同 2.8 插件
    Qraft Qraft 平台账号：OAuth2/手机号登录、access_token 到期状态、环境选择、计划自动刷新
    定时任务 同 2.10 Cron
    WSL 同 2.12 WSL 状态
    日志 日志查看器：来源过滤（主进程/渲染器/桥接/工具/沙盒/消息）、级别过滤（信息/警告/错误）、时间列、视图切换
    归档 同 2.4 归档管理
    隐私 隐私协议全文查阅
    文档 内置产品文档浏览
    反馈 用户反馈提交（自动附加运行日志发送到飞书）、反馈记录列表

    所有标签页均有 ErrorBoundary 保护：加载失败显示错误 + 重试按钮，不白屏。

    2.12 WSL 状态（WslStatusPage）¶

    • WSL 发行版选择与实时资源监控：CPU 使用率、内存使用率、磁盘使用率（/）、详细信息；
    • 手动刷新、无发行版时的引导提示。

    3. 技术边界¶

    3.1 架构形态¶

    • 双进程架构：Electron（Main 窗口/IPC 管理 + Preload contextBridge 白名单 + Renderer React UI）与 Python 运行时（miqi-bridge 子进程）通过 stdin/stdout JSON-line 通信——零网络端口、进程隔离、崩溃互不影响；
    • 打包版 miqi-bridge.exe 为 PyInstaller onefile 自包含二进制（内嵌 Python 3.12），用户机器无需安装 Python；支持 --check 自检；
    • 技术栈：Electron 35.2 / React 19.1 + TS 5.8 / Tailwind CSS 4 + Radix UI + Lucide / Python 3.11+（asyncio）/ Pydantic v2 / electron-vite + electron-builder。

    3.2 运行时边界（核心决策）¶

    • KUN runtime 是唯一演进路径：Thread → Turn → TurnItem → RuntimeEvent 数据模型；RuntimeSession 是唯一运行时入口；
    • 旧版 AgentLoop 已删除；69 个 legacy 协议方法仅为兼容保留：行为冻结、不新增、不扩展；
    • 新功能必须落在 typed 方法 + 运行时模块，禁止用宽松 schema 绕过类型化。

    3.3 协议边界¶

    • 152 个方法目录：83 个强类型（Pydantic v2）+ 69 个 legacy；JSON-RPC 2.0 信封；JSON Schema Draft 2020-12 目录；
    • 稳定性分级（stable/experimental/deprecated/legacy）+ 协议快照 SHA-256 治理：breaking change 必须更新快照并评审；
    • 参数校验先于运行时状态查找（类型错误直接 INVALID_PARAMS）；
    • TypeScript 类型由 Python 模型自动生成（export_app_protocol_ts.py），禁止手写漂移；
    • 客户端隔离：ClientSessionRegistry 按 (client_id, session_id) 隔离 + 空闲 TTL 驱逐。

    3.4 平台边界¶

    维度 边界内 边界外
    操作系统 Windows x64（第一优先级）、macOS x64/arm64、Linux 其他 OS/架构
    分发 Windows：portable / NSIS / MSI / zip；macOS：dmg / zip（hardenedRuntime） Docker（已移除）
    沙箱 Windows：WSL2 + bwrap；Linux：bwrap 原生 macOS：bwrap 不可用，沙箱能力不可用
    运行时版本 Python 3.11/3.12、Node.js 20+ Python ≤3.10、Node <20
    E2E 覆盖 Linux 全量；Windows(WSL) 全量；macOS 仅非沙箱 macOS 沙箱规格

    3.5 安全边界¶

    • 默认拒绝（deny-by-default）权限引擎；工具执行四阶段管道：审批 → 沙箱选择 → 执行 → 重试（指数退避）；
    • 审批策略：前端 AUTO/ASK/DENY 档位 + 运行时 ApprovalPolicy 五模式；39 种危险命令模式自动触发审批；
    • 沙箱：bwrap + LANDLOCK、per-session 隔离（tmpfs + bind mount、命名空间）、流式 I/O、自动清理；明确不支持 PTY（返回 UNSUPPORTED_FEATURE）；
    • 前端：contextBridge 白名单、IPC Zod 校验、HTML 预览走沙箱 iframe（SandboxHtmlFrame）；
    • 后端：AUTH 错误脱敏、API Key 文件 0600 权限、SSRF 防护（web_fetch 阻止私有网段与元数据地址）、会话作用域文件访问需全路径；
    • 合规：隐私协议版本化 + 首启确认门 + 安装协议页（NSIS）+ 回答底部免责声明。

    3.6 数据边界¶

    • 本地优先：全部数据存于 ~/.miqi/（MIQI_HOME 可重定向）——config.json、workspace/、SQLite（历史/账本/线程/代理任务图/任务追踪）+ JSONL（会话/记忆快照）；
    • 配置修改自动热生效；LLM 调用是唯一网络出口（另加渠道/反馈等用户主动配置的集成）。

    3.7 V1 明确不做（Non-goals）¶

    项 说明
    Web / 移动客户端 客户端形态仅桌面 + CLI/TUI + 消息渠道网关
    容器化部署 Dockerfile 已移除
    PTY / 交互式终端 协议层明确返回 UNSUPPORTED_FEATURE
    macOS 沙箱 bwrap 不可用，不在 V1 计划内
    legacy 协议扩展 新功能禁止落在 legacy 方法上
    多用户 / 云同步 本地优先，无账号体系与云端数据同步

    4. 边界速查表¶

    维度 V1 边界内 V1 边界外
    客户端 桌面（Electron）、CLI、TUI、Gateway、Cron Web、移动端
    平台 Windows x64、macOS x64/arm64、Linux 其他 OS/架构
    沙箱 Windows（WSL2+bwrap）、Linux（bwrap） macOS
    运行时 KUN runtime（RuntimeSession/AppServer），typed 方法 AgentLoop（已删除）、legacy 方法扩展
    协议 152 方法目录、JSON-RPC 2.0、快照哈希治理 未经评审的破坏性变更
    LLM Anthropic/OpenAI/Gemini/OpenRouter/DeepSeek + 自定义 Provider 本地模型推理
    工具执行 审批→沙箱→执行→重试 四阶段管道 绕过管道直接执行
