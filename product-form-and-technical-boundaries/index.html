    MiqroForge Desktop V1 产品形态及技术边界说明¶

    版本：1.0 ｜ 适用版本：MiqroForge Desktop 0.20.0（Alpha）｜ 依据：代码仓库现状（develop）

    0. 文档说明¶

    0.1 目的¶

    本文档定义 MiqroForge Desktop V1 的产品形态与技术边界，回答三个问题：

    1. 产品是什么——V1 以什么形态交付给用户；
    2. 技术怎么做——支撑产品形态的技术架构与约束；
    3. 边界在哪里——V1 明确做什么、不做什么、做到什么程度。

    0.2 读者¶

    产品、研发、测试、运营。技术团队用它对齐"新需求是否落在 V1 边界内"；外部协作方用它理解产品全貌。

    0.3 维护方式¶

    本文档随产品形态变化更新；涉及边界变更（新增/收缩能力）需在需求评审时同步修改本文档。

    1. 产品定义¶

    1.1 一句话定位¶

    MiqroForge Desktop 是一个本地优先的个人 AI 代理桌面工作台——将 Python AI 代理运行时引擎与 Electron 桌面界面结合，提供持久记忆、技能、文件操作、定时任务、多代理协作与可扩展工具生态，而非单纯的聊天机器人。

    1.2 名称与版本¶

    项 值 说明
    产品名 MiqroForge Desktop 对外书面名、界面名、安装包名（productName）
    内部标识 miqi-desktop / com.miqi.desktop 包名、appId 等内部标识符保留，不随更名修改
    当前版本 0.20.0 状态 Alpha
    许可证 MIT

    1.3 形态总述：一个运行时，多种前端¶

    V1 的核心资产是 Python 运行时引擎（以 AppServer 为协议边界），桌面应用是其主前端，但同一运行时还驱动 CLI、TUI、消息渠道网关（Gateway）与 Cron 调度。所有前端共享同一套会话、线程、工具与沙箱能力。

    2. 产品形态¶

    2.1 客户端形态¶

    形态 载体 定位
    桌面应用（主） Electron + React 面向个人用户的主产品形态，15+ 功能页面
    CLI Typer 命令行 终端操作入口（miqi 命令族）
    TUI Textual 终端界面 无 GUI 环境下的交互界面
    Gateway 消息渠道适配 飞书/钉钉/Slack/Discord/Telegram/QQ/Email/MoChat，统一 BaseChannel 抽象 + ACL 来源控制
    Cron 定时调度服务 基于 Cron 表达式的定时任务执行

    V1 不提供 Web 客户端与移动端客户端。

    2.2 技术形态：双进程架构¶

    ┌───────────────────────────────────────────────────────┐
│  Electron 桌面应用                                     │
│  ├─ Main（Node.js）：窗口管理、BridgeManager、IPC+Zod 校验 │
│  ├─ Preload：contextBridge 白名单 API                   │
│  └─ Renderer（Chromium）：React 19 + TS + Tailwind 4    │
├───────────────────────────────────────────────────────┤
│  Bridge：stdin/stdout JSON-line 协议（零网络端口）        │
├───────────────────────────────────────────────────────┤
│  Python 运行时（miqi-bridge，自包含子进程）              │
│  ├─ AppServer：类型化协议边界、方法注册、客户端隔离       │
│  ├─ RuntimeSession：唯一运行时入口                       │
│  ├─ TaskRunner / TurnRunner：回合执行与 LLM 工具循环     │
│  ├─ Thread/History/Ledger/Replay/Agent/Hooks 各 Runtime │
│  └─ 执行管道：审批 → 沙箱选择 → 执行 → 重试              │
└───────────────────────────────────────────────────────┘

    关键技术栈：

    层级 技术 版本
    桌面框架 Electron 35.2
    前端 UI React + TypeScript 19.1 / 5.8
    CSS / 组件 Tailwind CSS 4 + Radix UI + Lucide Icons 4.x
    后端引擎 Python（asyncio） 3.11+（打包内置 3.12.10）
    数据模型 Pydantic v2 2.12+
    CLI 框架 Typer 0.20+
    构建 electron-vite + electron-builder 3.1 / 26.0
    Python 打包 PyInstaller + Hatchling 6.20+

    设计要点：

    • 前后端通过 stdin/stdout JSON-line 通信而非 HTTP——零网络端口、进程隔离（Python 崩溃不影响 UI）、无端口冲突；
    • 打包后的 miqi-bridge.exe 为 PyInstaller onefile 自包含二进制，内嵌 Python 3.12 与全部依赖，目标机器无需安装 Python；支持 --check 自检（输出 JSON 环境报告）。

    2.3 分发形态¶

    平台 安装包 架构
    Windows portable 便携版 / NSIS 安装器 / MSI / zip x64
    macOS dmg / zip（hardenedRuntime + entitlements） x64 + arm64
    Linux 开发模式与 CI 验证为主（bwrap 原生沙箱环境） —
    • 发布渠道：main 分支产出稳定版，develop 分支产出 dev 预发布版（semantic-release 自动化，Conventional Commits 驱动版本号）；
    • 首次启动进入三阶段设置向导：环境检测 → WSL2 配置（仅 Windows）→ LLM 提供商配置；
    • 不提供 Docker 容器化部署（Dockerfile 已移除），部署形态即桌面安装包。

    2.4 功能形态¶

    V1 功能域总览：

    功能域 V1 范围
    智能对话 多轮对话、流式响应、工具调用可视化、随时中断、Markdown 渲染、180+ 语言代码高亮、文件编辑 diff 视图、文件附件
    办公文档 docx/pptx/xlsx/pdf 的读取/创建/编辑；23 种文件格式统一解析；中文排版预设（黑体标题+宋体正文、A4 公文页边距）；PDF 三层提取（快速提取→备用→OCR）
    文件管理 工作区文件树、内置文本编辑器、Markdown 预览、图片查看、模糊搜索、写入前快照/回滚/差异对比、文件监听
    记忆系统 长期记忆（USER.md / MEMORY.md）、经验教训（lessons）自改进、FTS5 全文 + 语义搜索回溯历史
    定时任务 5 字段 Cron 表达式 + 时区感知 ISO 时间戳，CronPage 面板管理
    技能系统 SKILL.md 目录格式（OpenClaw 兼容），15+ 内置技能，SkillHub 在线市场一键安装
    插件系统 plugin.json 清单（可含 MCP 服务器、技能、斜杠命令、生命周期钩子），从 GitHub/GitLab/Bitbucket 安装，PluginMarket 管理，pre_tool/post_tool/on_error 钩子
    MCP 集成 动态加载外部工具、15 秒进度心跳、单工具超时、连接复用、MCPsPage 管理
    网络能力 web_search（Brave/SearXNG/Hybrid）、web_fetch（readability 正文提取 + SSRF 防护）
    学术论文 arXiv 搜索、元数据获取、PDF 下载（自动检测付费墙）
    多代理 Agent 列表/状态监控、并发 spawn/kill、代理任务图（SQLite 持久化父子拓扑）
    会话管理 列表/归档/恢复、FTS5 搜索、导入/导出、懒加载无限滚动、批量操作
    回放调试 回合（turns）、时间线（timeline）、消息（messages）确定性回放检查
    开发工具 沙箱内 Shell 执行、Unified Diff 代码补丁、进程管理、GitHub（gh CLI）集成、SLURM 作业管理
    多渠道 飞书/Lark、钉钉、Slack、Discord、Telegram、QQ、Email、MoChat（Gateway 形态，ACL 限制来源）
    LLM 提供商 Anthropic、OpenAI、Google Gemini、OpenRouter、DeepSeek；可扩展 Provider 接口；故障转移链

    桌面功能页面（15+）：聊天、工作区、会话、计划、智能体、MCP、定时任务、记忆、经验、技能、插件、WSL 状态、权限、审批、设置（15+ 子标签），另有提供商、渠道、反馈与设置向导页面。

    2.5 数据形态：本地优先¶

    所有数据存储于本机 ~/.miqi/（可用 MIQI_HOME 环境变量重定向）：

    数据 存储 说明
    全局配置 config.json API Key、模型、审批、工具策略等；修改自动热生效，减少重启
    工作区 workspace/ Agent 文件操作默认根目录
    对话历史 / 事件账本 / 线程 SQLite HistoryRuntime + LedgerRuntime + ThreadRuntime，支持崩溃恢复
    代理任务图 / 任务追踪 SQLite（WAL + FTS5） AgentGraphStore / TaskTrace
    会话记录 / 记忆快照 JSONL 文件 追加式写入
    API Key 保护 文件权限 0600 本地加密场景以文件权限兜底

    零外部依赖：核心功能（对话、记忆、文件、定时任务）无需任何云服务；LLM 调用是唯一的网络出口。

    2.6 合规形态¶

    项 机制
    隐私协议 权威文本入库版本化（privacy.zh-CN.txt / privacy.en-US.txt），一份文本三处消费
    安装协议 NSIS 安装器协议页，拒绝即终止安装
    首次启动确认门 PrivacyConsentGate；同意状态本地持久化；协议版本更新后老用户重新确认
    设置页查阅 设置 → 隐私协议
    免责声明 每条 AI 回答底部常驻免责声明（独立文本维护）
    例外 MSI / portable / zip / DMG 无安装协议页，一律由首次启动确认门兜底

    3. 技术边界¶

    3.1 平台与版本边界¶

    维度 边界内 边界外
    操作系统 Windows（x64，第一优先级）、macOS（x64/arm64）、Linux 其他 OS / 架构
    运行时版本 Python 3.11/3.12、Node.js 20+ Python ≤3.10、Node <20
    沙箱 Windows：WSL2 + bwrap；Linux：bwrap 原生 macOS：bwrap 不可用，沙箱能力不可用
    测试矩阵 Linux 全量；Windows（WSL）全量（MIQI_RUN_SANDBOX_E2E=1）；macOS 仅非沙箱 macOS 沙箱规格

    3.2 运行时边界（核心决策）¶

    • KUN runtime 是唯一演进路径：以 Thread → Turn → TurnItem → RuntimeEvent 为数据模型（miqi/kun_runtime/ + miqi/runtime/）；
    • RuntimeSession 是唯一运行时入口，所有前端（桌面/CLI/TUI/Gateway/Cron）统一经它提交请求；
    • 旧版 AgentLoop 已删除（含兼容 shim），生产代码零引用；
    • 69 个 legacy 协议方法仅为向后兼容保留：行为冻结、不新增、不扩展、不修 bug（除非安全问题）；
    • 新功能必须落在 typed 方法 + 运行时模块：新增协议方法必须配套 Pydantic 请求/响应模型与类型化 handler，禁止用宽松 schema 绕过类型化。

    3.3 协议边界¶

    AppServer 是传输无关的协议边界，V1 协议治理规则如下：

    项 规则
    方法目录 共 152 个方法：83 个强类型（Pydantic v2）+ 69 个 legacy（宽松 {type:"object"} schema）
    信封格式 JSON-RPC 2.0（请求/响应/错误/事件四类信封）
    Schema 标准 JSON Schema Draft 2020-12，protocol/catalog 导出完整目录
    稳定性分级 每个方法标记 stable / experimental / deprecated / legacy
    参数校验 Pydantic 严格校验先于任何运行时状态查找——类型错误直接返回 INVALID_PARAMS，不触碰数据库/沙箱
    快照治理 协议快照 + SHA-256 哈希防意外破坏；任何 breaking change 必须更新快照并走评审
    类型同步 TypeScript 接口由 Python 模型自动生成（export_app_protocol_ts.py），禁止手写漂移
    客户端隔离 ClientSessionRegistry 按 (client_id, session_id) 隔离，空闲会话 TTL 驱逐
    连接握手 客户端连接时经 initialize 做能力协商

    3.4 能力边界¶

    LLM 提供商

    • 支持：Anthropic（Claude 系列）、OpenAI（GPT 系列）、Google Gemini、OpenRouter、DeepSeek，可扩展自定义 Provider；
    • 韧性：ErrorKind 错误分类（限流/服务端/Auth/超时/网络/内容过滤）、指数退避重试、尊重 Retry-After、ProviderFallbackChain 故障转移、所有调用显式超时；
    • 安全：Auth 错误脱敏，不向用户泄露原始 provider 异常；finish_reason="error" 不再伪装成正常回复。

    工具执行管道

    审批（ApprovalPolicy）→ 沙箱选择（SandboxPolicyEngine）→ 执行（ToolRegistry）→ 重试（指数退避）

    沙箱

    • bwrap 沙箱 + LANDLOCK 文件系统网络策略；per-session 容器化（tmpfs + bind mount、进程/PID/UTS/User 命名空间）；
    • 流式 stdin/stdout I/O、取消、会话结束自动销毁、异常退出重启自清理、FIFO 驱逐上限（10）；
    • Windows 通过 WSL2 隔离执行环境；沙箱命名空间按 client_id:session_key 双重隔离；
    • 明确不支持 PTY：command/exec/resize、process/resizePty 返回 UNSUPPORTED_FEATURE；
    • macOS 无沙箱：bwrap 不可用，命令执行能力降级（E2E 沙箱规格在 macOS CI 排除）。

    文件边界

    • 默认限制在工作区目录内（restrictToWorkspace），可配置 extra_roots 与 auto_user_dirs 扩展；
    • 所有写入操作前自动创建内容快照，支持回滚/对比/接受/撤回；
    • 会话作用域文件访问需全路径（sessions/<key>/files/<name>），不做裸名解析。

    网络边界

    • web_fetch 内置 SSRF 防护：阻止私有 IP 网段与云元数据服务地址；
    • 网络审批受 ApprovalPolicy 管控。

    文档边界

    • 统一解析 23 种格式：Office 系列（PDF/DOCX/DOC/ODT/PPTX/PPT/ODP/XLSX/XLS/ODS）、标记语言（Markdown/HTML）、数据文件（CSV/JSON/XML/YAML/ENV/LOG/SQL/INI/TOML/HTACCESS）、脚本文本；
    • PDF 三层提取（pypdfium2 → pypdf → Tesseract OCR），自动发现系统 CJK 字体。

    3.5 安全边界¶

    层 机制
    权限引擎 默认拒绝（deny-by-default）；工作区隔离；快照保护
    审批策略 前端 AUTO（自动批准安全工具）/ ASK（每次确认）/ DENY（拒绝）；运行时 ApprovalPolicy 五模式（unless-trusted/on-failure/on-request/granular/never），对可信类别抑制 APPROVAL_REQUIRED
    危险命令 39 种危险命令模式自动触发审批；ExecPolicy DSL（CommandRule/NetworkRule/FilesystemRule，deny-wins 优先级）
    前端 contextBridge 白名单暴露 API；IPC 层 Zod 参数校验；渲染进程无 Node 能力
    后端 协议参数严格校验先行；客户端/会话双重隔离 + TTL；AUTH 错误脱敏；API Key 文件 0600
    钩子 13 个生命周期点（SESSION_START/TURN_START/PRE_COMPACT/SUBAGENT_START 等）统一经 HooksRuntime 触发，支持 continue/block/modify
    供应链 插件/技能安装有版本与状态管理，卸载即清理；MCP 服务器独立子进程运行

    3.6 配置边界¶

    • 全局配置 ~/.miqi/config.json（MIQI_HOME 可重定向）；
    • 配置修改自动热生效，减少重启要求；
    • 环境变量边界：MIQI_PYTHON_PATH（自定义解释器）、MIQI_AGENTS__DEFAULTS__MODEL（默认模型覆盖）等；
    • 打包环境与开发环境自动区分：存在 resources/miqi-bridge.exe 即认为环境就绪，开发环境按 MIQI_PYTHON_PATH → uv → .venv → python3 → python 顺序探测解释器。

    3.7 兼容性边界¶

    承诺 范围
    协议方法不删除 152 个方法全部保留在目录中；legacy 方法行为冻结不变
    老会话数据兼容 旧 session 无 owner_client_id 时 claim-on-first-touch 自动迁移；历史数据只读兼容
    打包自包含 用户机器无需 Python、无需 VC++ 运行库（构建机需 VC++ 2015-2022 x64 Redistributable，仅影响打包，不影响用户）
    前端不动协议 协议类型由 Python 模型生成，杜绝前后端契约漂移
    测试隔离 所有测试使用 tmp_path，禁止读写真实 ~/.miqi

    3.8 V1 明确不做（Non-goals）¶

    项 说明
    Web / 移动客户端 V1 客户端形态仅桌面 + CLI/TUI + 消息渠道网关
    容器化部署 Dockerfile 已移除，部署形态为桌面安装包
    PTY / 交互式终端 协议层明确返回 UNSUPPORTED_FEATURE
    macOS 沙箱 bwrap 不可用，不在 V1 计划内
    legacy 协议扩展 新功能禁止落在 legacy 方法上
    多用户 / 云同步 本地优先，不做账号体系与云端数据同步

    4. 边界速查表¶

    维度 V1 边界内 V1 边界外
    客户端 桌面（Electron）、CLI、TUI、Gateway、Cron Web、移动端
    平台 Windows x64、macOS x64/arm64、Linux 其他 OS/架构
    沙箱 Windows（WSL2+bwrap）、Linux（bwrap） macOS
    运行时 KUN runtime（RuntimeSession/AppServer），typed 方法 AgentLoop（已删除）、legacy 方法扩展
    协议 152 方法目录、JSON-RPC 2.0、快照哈希治理 破坏性变更不经评审
    LLM Anthropic/OpenAI/Gemini/OpenRouter/DeepSeek + 自定义 本地模型推理
    工具执行 审批→沙箱→执行→重试 四阶段管道 绕过管道直接执行
    终端能力 流式 I/O、进程管理 PTY
    文件 工作区 + 快照回滚 + 监听搜索 不受限的全盘写入
    网络 web_search/web_fetch（SSRF 防护） 无防护的任意抓取
    文档 23 种格式解析 + docx/pptx/xlsx/pdf 读写 视频/音频处理
    数据 本地 SQLite + JSONL（~/.miqi） 云存储/多端同步
    合规 隐私协议 + 确认门 + 免责声明 企业级合规认证
    分发 桌面安装包（portable/NSIS/MSI/dmg/zip） Docker 镜像
